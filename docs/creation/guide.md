# Building original CS2 addons with an AI agent

How the original minigames were made: Hellmatch (Doom-style deathmatch, 4 arenas × 16), Space Racer (32-car anti-grav racer), mg_trenchwarfare
(WW1 trenches with mortars and biplanes), Puppet Brawl (2.5D fighter), mg_deku_tree (hollow-tree KZ with monsters) and a grid bomb-arena game.
Each one runs **entirely inside one map**: no server plugins, everything generated by Python/Node tools and a cs_script.

Source repos (all MIT code): [hellmatch-cs2](https://github.com/skink52/hellmatch-cs2), [space-racer-cs2](https://github.com/skink52/space-racer-cs2),
[trenchwarfare-cs2](https://github.com/skink52/trenchwarfare-cs2), [cs2-fighter on the anim-v3 branch](https://github.com/skink52/cs2-fighter/tree/anim-v3)
(Puppet Brawl's current code; `main` is the 14 Oct baseline without `tools/anim/`). The reusable parts are collected, project-neutral, in [`create/`](../../create).

This page is the workflow. Detail lives in: [models.md](models.md) (props, voxels, player models, animated rigs), [hud.md](hud.md) (Panorama HUD, loading
screens, radar), [sound.md](sound.md), [custom-weapons.md](custom-weapons.md), [workshop.md](workshop.md), and [templates/](templates/) (project docs).
Engine facts: [../reference/cs2-gotchas.md](../reference/cs2-gotchas.md); script API patterns: [../reference/cs_script-notes.md](../reference/cs_script-notes.md).

## 1. Project shape

A typical repo (per project, not in this repo; names vary):

```
src/core/ or src/core_*.js     the game rules in plain JavaScript, no engine calls (runs in Node for tests, sims and browser previews)
src/cs2/  or src/cs2_*.js      the CS2 adapter: pawn parking + camera, input, prop-pool rendering, HUD, sounds, kills, round control, chat commands
tools/                         Python/Node generators: models, materials, textures, HUD, sounds, loading screens, radar, map writer
tools/build.mjs                joins core + generated data + adapter into maps/scripts/<name>.js, and core + data into a Node test module
tools/build_all.sh             the whole build in order (see below)
test/                          sims on the pure core, a mock engine running the real script, tsconfig + point_script.d.ts
preview/                       software renders: levels, models, HUD at 16:9 / 21:9 / 4:3, chase or fight camera
out/addon/ -> content\csgo_addons\<addon>\      out/game/ -> game\csgo_addons\<addon>\
ref/                           the map as last saved in Hammer, Valve template files (not committed to public repos)
```

Hellmatch and Space Racer use `src/core/` + `src/cs2/` folders and `test/sim.cjs` / `test/mock_cs2.mjs`; Puppet Brawl uses flat `src/core_*.js` /
`src/cs2_*.js` and `test/sim_core.mjs`, `sim_cs2.mjs`, `mechanics.mjs`, `balance.mjs`.

- **Why split core and adapter:** the rules can be simulated thousands of times in Node (balance, durations, bot behaviour) and the CS2 side stays thin.
- **One source of truth.** The core decides which frames, strings, levels and clips exist; generators read it (Hellmatch's build pulls sprite frame lists and
  HUD strings out of the core with `node -e`; mg_trenchwarfare's `tools/layout.py` feeds the map writer, the renders and the script `CONFIG`).
  Puppet Brawl goes further: **animation is the source of truth**: build core → generate clips from its move table → bake 2D hit/hurt tracks from
  the clips → rebuild core with the tracks embedded (`tools/make.mjs`, ~10 s), so what you see is what hits.
- The build bakes generated data (level tables, model lists, HUD string indexes, glyph widths, music lengths) into the script as constants.
- One `CONFIG` object at the top of the script holds every tunable (round length, arena sizes, damage, cvars applied, an `APPLY_CVARS` opt-out for servers).
- **Templates:** [`create/build/build.mjs`](../../create/build/build.mjs) (config-driven script assembler) and
  [`create/build/build_all.example.sh`](../../create/build/build_all.example.sh), the reference build order:
  test module → models → HUD → **HUD check (stops the build)** → sounds + `merge_snd` → sky, loading slides (checked against the HUD preloads), radar,
  icon → map (user's last save or template, then the generated layer) → script → copy README/TESTING/CREDITS into `out/addon` and `out/game`.
  Each generator checks the contract with the next one (unknown panel ids, unpreloaded slides, missing models fail the build or the mock).
- **Switches** (environment, one prefix per project, e.g. `SPR_`, `FDM_`): `<X>_NAME` renames map/script/HUD files, `<X>_CURRENT_VMAP` = the map as last saved
  in Hammer (generated content is layered onto it), `<X>_SOUNDEVENTS` = the addon's live `soundevents_addon.vsndevts` to merge into.
- Run generators with `python3 -I` (isolated mode: nothing in the working folder can shadow a module).

## 2. Writing the map without Hammer

- The map is a binary DMX `.vmap`. [`create/dmx.py`](../../create/dmx.py) reads/writes it losslessly; [`create/vmaplib.py`](../../create/vmaplib.py) writes entities,
  meshes and nodes; [`create/vmesh.py`](../../create/vmesh.py) writes open meshes; [`create/vmapgen.py`](../../create/vmapgen.py) holds the recipes below
  (rooms, shells, hints, cache room, sound events, template pool, nav seed, probes, terrain, lightmap-res shells, `finish()`, `EditKeeper`).
  `tools/vmapedit.py` (porting side) also reads the importer's keyvalues2 maps.
- **Start from the user's map** (`<X>_CURRENT_VMAP` or argv) and layer generated content on top. A fresh project starts from the addon template map
  (sky, lighting, probes, post-processing, team intro, nav). On the first run `finish()` drops Hammer's unnamed sample entities (`point_script`,
  `custom_hud_layout`, `point_soundevent`, `point_template`, `prop_dynamic`) and the default box mesh (no vis group).
- **Clone entities from the user's map** (`vmapgen.clone`): place one sample of each class in Hammer and copy its full key set, so every FGD key is present.
  Entities written with only classname + a few keys get defaults when Hammer re-saves.
- **Tag everything generated** with a vis group (`customVisGroup`: `tw_gen`, `fdm_env`, `spr_env`) so a re-run replaces only its own nodes.
  mg_trenchwarfare also uses `tw_user` (adopted user edits) and `tw_sky` (skybox map).
- **Keep the prefix in step:** after adding or removing entities/materials, rewrite `map_asset_references` (add used materials incl. tool materials such as
  `toolsnavattribute.vmat`, strip stale ones like `toolsskybox.vmat`) and `map_subasset_reference_types/names/counts` from the real entity counts
  (`vmapgen.finish` / `rewrite_refs`). Binary DMX quirks (prefix element, array type codes, string tables) are in `create/dmx.py`'s header.
- **Add only what's missing** on rebuilds: cache props and `point_soundevent`s only for models/sounds the user's map doesn't already have, on a free grid that
  avoids existing ones (`vmapgen.cache_room` / `sound_events`, `only_missing=True`).

### Regenerating keeps edits only if you set it up

> **Warning.** A full regeneration replaces everything in the generator's vis group. mg_trenchwarfare's generator also deletes **every mesh with no vis group**
> ("template sample geometry") and every entity of the classes it owns (`light_environment`, `env_sky`, `env_cubemap_fog`, `env_combined_light_probe_volume`,
> `post_processing_volume`, `env_soundscape`, `func_buyzone`, `info_player_*`, `point_worldtext`, team intro/select, `end_of_match`, `cs_minimap_boundary`,
> `point_nav_walkable`), whatever their group. So the mapper's own lighting, probes, spawns and ungrouped meshes are removed. Tell the mapper to put
> hand-made meshes in their own vis group, and keep owned-class lists short (`vmapgen.finish(drop_classes=...)`, `GENERATOR_OWNS_EXAMPLE`).

Edit preservation (mg_trenchwarfare `make_map.py`, now `vmapgen.EditKeeper`):
- Run as `gen.py <user's latest vmap> <out> <addon> <previous generated vmap>` (the file the user was last given). Keep every delivery as `gen_N.vmap`.
- A generated object in the user's map with no match in the previous output is a user edit. Match: same class + model, origin within 0.75 u, angles within 1°
  (Hammer re-saves floats); meshes by material + rounded bbox + vertex count. Edits are re-tagged to the user group and kept.
- The originals they replaced are recorded in `user_edits.json` and never generated again.
- An adopted edit: a user copy within 12 u / 8° of something the generator now makes itself is dropped (the rule now produces it).
- The user's placements are registered as placer obstacles.

**RNG cascade:** once user edits act as obstacles, everything placed randomly after them shifts. Give each section its own seeded generator
(`np.random.RandomState(<seed>)` per section; mg_trenchwarfare's skirmish woods: "own rng: nothing above shifts"). Until every section has one, use delta patches.

**Delta patches** for late changes ([`create/patch_vmap.py`](../../create/patch_vmap.py)): apply small changes straight onto the user's latest vmap with no
regeneration. Rules: idempotent (skip an entity whose targetname, or class + model at the rounded origin, already exists), never touch nodes you didn't add,
and rewrite the asset references and per-class counts at the end. One-off passes kept as files (Puppet Brawl's `tools/history/` with a README) document what
was applied.

Checks before handing a map over: `create/check_mesh.py <vmap>` (half-edge validity), `tools/vmap_preview.py <vmap> out.png` (top-down + corners).

## 3. World layout conventions

- **Multi-arena maps:** every arena/level/track sits in its own box in the void, boxes asserted not to overlap (`vmapgen.assert_no_overlap`). Each box is
  enclosed in a moondome (sky-material shell) with a `tools/skybox` shell 1 unit inside it for environment lighting, **single-sky maps only**: several skies
  need one moondome per box with its own sky material and no toolsskybox shell (Space Racer). For the new `toolsskyboxocclude` material see
  [cs2-gotchas, Sky and world](../reference/cs2-gotchas.md#sky-and-world) (untested).
- **Vis hints:** Lowest over everything (the void), Low only over the playable band (Space Racer: a chain of Low hints along the track centre line, 40 samples per
  chunk, padded 900 sideways, 350 down, 1100 up; `vmapgen.path_hints`), Lower (`hintType` 8) for big volumes, Medium only around very complex meshes.
  Sky shells around sealed rooms: Exclude from Vis.
- **Lighting:** enough stationary lights that weapons aren't black; one `env_combined_light_probe_volume` per room/arena (`vmapgen.probe_volume`);
  `toolslightmapres` shells over the player space (`vmapgen.lmres_*`: 64-grid occupancy, floor −8 to +128); probe-lit (`bakelighting 0`) foliage and small props;
  ≤ 4 shadowed lights overlapping. Probe sizes and lamp keys: [cs2-gotchas, lighting](../reference/cs2-gotchas.md#lighting-materials-and-rendering).
- **Lobby + pawn booth:** a lobby room (join by chat command or automatically; Hellmatch dropped its join pads), a sealed booth where parked pawns wait,
  a model cache room, and a `func_nav_markup` WALKABLESEED for bots.
- **Outdoor environment** (mg_trenchwarfare, cloned from template entities): `light_environment` `directlight 3`, `skyintensity 1.6`, `fog 1`;
  `env_cubemap_fog` start 400, end 7500, falloff 1.25, height fog 300–2600, max opacity 0.85, `cubemapfogskyentity sky`; `env_volumetric_fog_controller`
  `IsMaster 1`, `FogStrength 0.6`, `DrawDistance 1600`, `FadeInStart/End 40/300`, `IndirectEnabled 1`, `IndirectVoxelDim 256`, `NoiseStrength 0.55`,
  `NoiseScale .004 .004 .01`; `post_processing_volume` `master 1`, exposure 0.6–1.8, `spawnflags 4097`; `env_soundscape` `soundscape Nothing`,
  `enablesoundevent 1`, `soundevent <your soundscape event>` ([sound.md](sound.md#soundscapes)).
- **Terrain** (`vmapgen.Terrain`, from mg_trenchwarfare): 512-unit tiles, cell size 32/64/128 by distance from play, coarser-neighbour edges interpolated so
  seams don't crack; `fix_pinches()` makes diagonal-only cell links manifold; spawn height `surf_z()` = bilinear height + 0.25 × the cell's z range, max over
  3×3 samples. Parapets as a separate open-mesh layer; Valve blend materials with vertex paint ([gotchas](../reference/cs2-gotchas.md#lighting-materials-and-rendering)).
- **Water sheets:** never overlapping, depth ≤ 5 u, each sheet one cell past the shore unless a lower basin is next to it.
- **Ladders:** a `toolsinvisibleladder_wood.vmat` climb volume plus a non-solid ladder prop; cut gaps in `toolsplayerclip` slabs.
- **Teleport targets:** the script teleports to an entity's origin (+4 z), so any point entity works; `info_teleport_destination` shows the player hull in Hammer.
- **KZ maps:** `trigger_multiple` `timer_startzone` / `timer_endzone` and `info_teleport_destination` `timer_start` (the no-FGD convention timer plugins read).

### Skies

- `sky.vmat`: `shader "sky.vfx"`, `F_TEXTURE_FORMAT2 1`, `SkyTexture "<2:1 equirect png>"`, `g_flBrightnessExposureBias "0.000"` (Hellmatch, Space Racer;
  which keys are needed is unverified, see [gotchas](../reference/cs2-gotchas.md#sky-and-world)).
- Moondome: `shader "csgo_moondome.vfx"`, `F_DO_NOT_CAST_SHADOWS 1`, `TextureCubeMap "<same equirect png>"`, `g_flCubeParallax "0.000"`, `g_bFogEnabled "0"`,
  a 16×16 white `TextureColor`. `vmapgen.sky_files()` writes both; [`create/skies.py`](../../create/skies.py) paints pixel-art panoramas.
- **3D skybox** (mg_trenchwarfare): a separate `<map>_3dskybox.vmap` (`mapUsageType skybox`, own `light_environment`/`env_sky`, `sky_camera` scale 16 at its
  origin) holding a terrain ring at 1/16 scale that starts at the main map's edge ([`create/make_skybox.py`](../../create/make_skybox.py)); the main map gets the
  `skybox_reference` above (the mapper moved it from (0,0,−12000) to the origin). Skybox content draws behind everything, so **anything players or vehicles
  can reach must be in the main map**: mg_trenchwarfare's sky shell is at map half-extents + 256, z −700…6400, with the air box x ±6400, y ±5400, z ≤ 5000 inside it.

## 4. The script

API facts and patterns live in [cs_script-notes.md](../reference/cs_script-notes.md); this is the shape of a game script.

- **Instances/arenas:** one `Arena` object per arena, each ticked inside its own try/catch. Players assigned per round; sizes from a table (under 16 all in one,
  16 → 8+8, 31 → 16+15, 32 → 8×4). Late joiners take a bot's place when no arena has room (Hellmatch).
- **Rendering by prop pool:** everything that moves is a pooled `prop_dynamic` from the `point_template`, model swapped by `SetModel`, moved with `Move` every
  tick (Teleport only for jumps > ~400 u), colour via `SetColor`, team colours and animated textures via the `Skin` input ([models.md](models.md#skins-and-animated-textures)).
  Effects are pooled with hard caps (dropped, never spawned unbounded).
- **Rounds:** the script runs the round (`mp_ignore_round_win_conditions 1`), ends it with `FireWinCondition`, varies the mode, lets finished players spectate,
  caps time with `SetRoundRemainingTime`; locked rounds queue new players. Fallback: if CS2 hasn't ended the round 20 s after the game did (warmup, a plugin),
  start the next one yourself (Space Racer `ROUND_END_WAIT`).
- **Next-mode vote** (Hellmatch): ballot keys that don't move you (`ATTACK`, `ATTACK2`, `USE`, `RELOAD`, `LOOK_AT_WEAPON`), ignore presses in the first second
  (fire held through round end), weight `1 + 2 × frags / top frags`, never a third round of one mode, fall back to the next-best when the winner can't be played.
- **Kill credit:** real CS2 kills via `TakeDamage` so rank plugins count them; podium splits (50/30/20 % of the arena's losers) for games without natural kills.
  mg_trenchwarfare's mortar assist (the loader deals a non-lethal share, ≥ 55, before the firer's kill) is a design choice, **unverified** in game.
  Details and the respawn watchdog: [cs_script-notes, kills](../reference/cs_script-notes.md#kills-rounds-and-score).
- **AFK and robustness:** AFK on input (not position), slot ownership checked once a second, full HUD reset on activate/team change, re-validate after restarts.
- **Version banner on load** with counts and what was found, e.g. `[hellmatch] v0.2.0 ready: 32 levels, 505 sprite models, HUD on, prop template on`
  (`MISSING` when an entity isn't found), plus a once-a-minute `script time: avg X ms, max Y ms per server tick` line.
- **Bots:** CS2 bots fill slots; the script drives them with its own AI (Space Racer's lane-keeping cut car contact 30%).
- **Game feel** (Puppet Brawl, `core_4_game.js` `impactOf`): impact tier 0–3 from the hit (heavy sound → 2, damage ≥ 6 → 1, launch/knockdown ≥ 2, specials ≥ 2);
  per tier hitstop 7/9/12/14 frames (+4 on a counter, KO 18), camera kick 1.5/3/5.5/8, spark size 9/11/14/17; punch-in 0.06 on tier 3, 0.16 on KO; shake
  0.8 / 1.3 (tier 3) / 3 (KO); KO slow-mo 1.6 s stepping the sim one frame in three. Layered hit sounds, block effects, landing dust, a COUNTER callout.
- **Script physics lesson** (Puppet Brawl): `airborne = y > 0.01 || vy > 0.01` let bodies landing in (0, 0.01] glide forever. Use `y > 0 || vy > 0`, always run air
  physics in launch states, and force a body down after a timeout (`AIR_TIMEOUT` 150 frames).
- **Aircraft** (mg_trenchwarfare biplanes): Source pitch + is nose down (`PITCH_SIGN −1`); steer yaw and pitch separately (a quaternion slerp flipped through
  the vertical); ground trace ignores every aircraft (`ignoreEntity` takes an array); touching the ground or world = crash, "PULL UP" below 320 u; a soft
  flight box with a hard clamp at box + 600; propellers are split-out props spun by roll += 900–2400°/s with throttle, hub offset rotated by the body's
  angles; every 3rd round a tracer prop flown at 9000 u/s; gunsight pip 1600 u ahead or at the first obstacle; bomb-sight ring at the predicted ballistic
  landing; fx props parked at z −3600 when unused; pilot pawn hidden with `SetModelScale(0.02)`. Mock-tested 240 s with 24 players.
- **Set dressing from props:** footprints for every prop so optional dressing never intersects ([`create/placer.py`](../../create/placer.py), oriented boxes on
  a spatial hash). Its stock-model bounds are a hand-entered, conservative table; real bounds of compiled stock props come from
  [`create/s2/prop_mesh.mjs`](../../create/s2/prop_mesh.mjs) (cs2-fighter's `vmdl_c` mesh reader). `Placer.audit()` lists interpenetrating pairs.
- **Cosmetic ambience** (mg_trenchwarfare): scripted shell bursts every 4–13 s at ≥ 550 u from any player.
- **Performance:** [cs_script-notes, performance](../reference/cs_script-notes.md#performance). Measure on the mock before shipping.

## 6. Testing before CS2

Layers, cheapest first. Keep the CS2 checklist for what only the game can answer.

1. **Core sims** (`node test/sim.cjs` or `sim_core.mjs`): the pure game with bots; fail on exceptions, NaNs, stuck states, unfinished rounds.
   - **Balance:** `tune=<file.json>` overrides rules/stats without rebuilding; `even` equal car counts; average over bot skill levels; know the noise floor first
     (Space Racer ±0.3 wins/100; Puppet Brawl treats ±5% as noise over every pairing × side × CPU level, 600 s × 3 seeds) and record the table in the handover.
   - **Soak + probes:** CPU-only matches in every mode; for each in-game bug write a targeted probe that counts it (Puppet Brawl's stuck-in-air probe went 107 → 0).
   - **Deterministic mechanics tests** with an input driver that has the same edge detection as the adapter (`mechanics.mjs`: every special by both input paths,
     throws, blocks, juggles, leaving in every phase).
   - **Per-level audit** (Hellmatch `audit_monsters.cjs`): run every level with bots and count per second things outside the outline, inside walls, floating,
     stuck > 10 s, idle, spawn failures, slow tics, HUD text over its slot count.
   - **Equivalence fuzzing** before/after a geometry optimisation: Hellmatch compared 192k random path traces and sight checks over all levels, 0 differences.
2. **Mock engine**: the real script on a stand-in API ([`create/test/mock_point_script.mjs`](../../create/test/mock_point_script.mjs), flags in
   [create/test/README.md](../../create/test/README.md); the project mocks are richer). Patterns worth using:
   - **Trace diff:** `seed=N trace=a.txt` on the old build and `trace=b.txt` on the new one, diff; the observable state (HUD classes per slot, entity
     pos/model/skin/alpha, sounds, kills) must be identical. Seed `Date.now` too. Space Racer cut script time by ⅔ this way "with nothing looking different".
   - **`calls`:** engine calls per tick and the top callers. **Perf:** p50/p90/p99/p99.9 think time after a warm-up, ticks over 16 ms listed; profile with
     `node --cpu-prof`.
   - **Scenario flags** for multiplayer edge cases: churn (joins/leaves/team swaps), silent slot reuse without disconnect, `OnPlayerReset` before
     `OnPlayerTeamChanged`, no respawn, warmup, unassigned players, HUD changes dropped until a client picks a team, held keys, input masks meaning ALL.
   - **Engine strictness:** throw on calls to removed entities, `SetModel` to a model not in `out/addon/models`, positions beyond ±16384 or non-finite,
     unknown HUD panel ids or CSS classes, a prop `Teleport`ed 3+ ticks running (CS2 doesn't draw it).
   - **End-to-end assertions** (Puppet Brawl `sim_cs2.mjs`): join freezes the pawn, camera CONTROLLED and unparented, HUD shown per player, every requested
     clip (incl. `_m`) exists in the rig, hitstop sends rate 0, round restart releases players, script reload re-inits, particles capped.
   - **Camera check on a rotated stage** (Puppet Brawl `cam_check.mjs`: stage turned 30° so yaw maths is exercised).
3. **Type check:** `sh create/test/tscheck.sh <script>` (a strict variant with `strictNullChecks` catches more).
4. **HUD check:** `python3 -I create/hud_check.py` as a build gate ([hud.md](hud.md#checking-the-layout-before-cs2)).
5. **Animation validator** as a gate after every clip change ([models.md](models.md#checks-without-cs2)).
6. **Overlap audit:** after placement, `Placer.audit()` → `overlaps.json` with the top model pairs.
7. **Software previews:** model turntables (`create/render.py`), scene and camera views ([`create/smd_view.py`](../../create/smd_view.py), CS2's 106° 16:9 FOV),
   map views (`tools/vmap_preview.py`), first-person views of a generated scene (mg_trenchwarfare `fp.sh name eye target`), agent animation sheets
   (`create/anim/preview.mjs`). Hellmatch's WebGL viewer runs headless: Playwright Chromium with
   `--use-gl=angle --use-angle=swiftshader --enable-unsafe-swiftshader`, served by `python3 -m http.server`, the page sets `document.title = "done"` when drawn.
8. **The mapper's in-game test:** a short checklist ([templates/TESTING.md](templates/TESTING.md)). Anything not reported as failing passed.

## 7. Delivery

- The mapper keeps Hammer closed while files are written and backs up the map. Always read the latest `.vmap` before generating.
- Send only changed files. Bulk files go in zips under ~20 MB with an unpack `.bat`. The bat applies each zip once and never contains the user's `.vmap` or the
  live script. Recipe (fixed after mg_trenchwarfare re-extracted old zips over the mapper's edits): applied list in `logs\<addon>_applied.txt`, written with
  `(echo name)>>list` (plain `echo name >> list` leaves a trailing space so `findstr /x` never matches), checked with `findstr /b`, pre-seeded with zips
  already applied, looping over the numbered zips (`tw2..tw99`). Bridge limits: [ai-workflow](../reference/ai-workflow.md#transfer-limits-and-traps).
- **Compile:** the Hammer map build compiles models, materials, sounds, HUD and script; the command-line runner (`run_build.bat`) pre-compiles assets first,
  but its pre-pass covers only `maps/scripts/*.js` and `panorama/*.vtex` among scripts/Panorama. So `scripts/*.js` (older layout) and
  `panorama/layout/custom_game/*.xml`, `panorama/styles/custom_game/*.css` **always** need `resourcecompiler.exe -f -i <file>`; a model only the script uses
  is caught by the `models/*.vmdl` pass, or compile it with `resourcecompiler -i <vmdl>`.
- The version banner (§4) tells the mapper which build is running. Ship README, TESTING and CREDITS inside the addon ([§8](#8-project-docs)).
- After in-game testing, record what was verified and what wasn't in the handover doc.
