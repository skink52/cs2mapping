# CS2 gotchas: what breaks, and what fixed it

Collected from the ports in this repo and from the original cs_script addons (Hellmatch, Space Racer, mg_trenchwarfare, Puppet Brawl,
mg_deku_tree, the bomb-arena game). Port names in the Fix column point at `ports/<addon>/`; project names point at the project repos
listed in the [README](../../README.md#projects-built-with-this). Pipeline fixes run automatically in stage C (see
[pipeline.md](../porting/pipeline.md)). **Unverified** means it had not been confirmed in CS2 when it was written down. Detailed write-ups for
the original addons are in [../creation/](../creation/); cs_script API details are in [cs_script-notes.md](cs_script-notes.md).

## Valve's importer

| Problem | Fix |
|---|---|
| The importer fails with "pak01.vpk / Failed to load file (invalid)" while `game\bin\win64\vpk.signatures` exists, and Steam restores the file after updates. | Rename it (`run_import.bat` does it every run). |
| A material or texture file name containing `+` (CS:GO animated-texture frames such as `+0sign_compmon4_hr`) | resourcecompiler: "Non-fused-child compiles cannot contain fused delimiter '+'", so the material never compiles and the build stops (mg_n64_goldeneye). | Copy the vmat/png to a name without the `+N` prefix and repoint the meshes and the vmap's `map_asset_references`. Stage C flags them. |
| `item_assaultsuit` (or any `item_*`) in a `game_player_equip` `weaponN` slot | The server crashes while loading the map (null vtable call in the equip's weapon handling; mg_n64_goldeneye, mg_mario_party's armour-only `PlayerEquip` on 4 Nov 2026: the dump's stack holds the item name and `PlayerEquip`, the console shows nothing after `execing maps/<map>.cfg`). `mapcheck.py` reports it as `equip_item`. | Keep only `weapon_*` in the slots and give items from cs_script (`pawn.GiveNamedItem("item_assaultsuit")`), fired next to the equip's trigger. Stage C does this. |
| Valve's importer writes `brightness = nan` on CS:GO lights whose intensity is below ~265 (it puts log2(I/265) in `brightness_legacy` and takes log2 again). | Hammer turns them into 0 on save; a command-line build gets nan. Stage C sets 0; `stage_d.py lightbright` rebuilds real values from the VMF. |
| Valve's importer turns every CS:GO light colour into a 6600 K white (colour temperature) and ignores `_lightHDR` / `_lightscaleHDR`; lights that start dark, flicker (`style`) or are switched by outputs import as Static, which can't be switched. | Stage C `lights` / stage D `relight` delete and rebuild every light from the VMF; `lightbright` fixes them in place. Both write the VMF colour with `colormode 0`, use the HDR values, set `enabled 0` for start-dark lights and `directlight 2` for switched/styled ones, and copy the style pattern to `light_style`. From cs2-slop-porting `rebuild_lighting.py` (MIT), 30 Oct 2026. |
| Source 1 water is lit by the lightmap; a CS2 water volume with no light inside is dark underwater. | Stage D `water` adds dim unshadowed lights under the surface where no light reaches (cs2-slop-porting method). |
| env_steam heat wave: the distortion lives in `sprites/heatwave.vmt` (`$refractamount -0.007`), not on the entity. 0.25 (stock CS2 reference particle) is far too strong. | `steam` uses -0.007. |
| Static overlays on brush entities (func_breakable, doors, func_brush) | CS2 static overlays don't project onto entity meshes, so the decal is missing (and wouldn't move with the entity). Stage C `ovlquads` turns one-entity overlays into parented translucent quads; mixed ones stay overlays (TO CHECK). Method from cs2-slop-porting (MIT), 30 Oct 2026. |
| `vmapedit.Map.import_subtree` copies list attributes one level deep: vectors in position/texcoord arrays stay shared with the source. | Deep-copy after cloning before editing vertices (as `ovlquad.py` does). |
| `run_fixrefs.bat` / `modelsfromrefs.py` stops with "Expecting importfilelist". | The refs file must be Valve's KeyValues format: `importfilelist { "file" "models/x.mdl" ... }` (CRLF), not a bare list of paths (`gibfix.write_refs` writes it; ba_jail_keimusho's hand-written one didn't). |
| `import_map_community.py` waits for Enter/Esc, so it can't run unattended. | `scripts/make_import_map_auto.py` makes a copy without the prompt. |
| The importer aborts the **whole** run on the first model or material it can't handle (`utlc.RunCommand` → `Error()` → `sys.exit(1)`). On a big map "it died" can mean anything from "barely started" to "only the compile didn't happen". | Run `post_import_cleanup.py` afterwards: it picks up where the importer stopped and reports what's still missing. |
| The importer fails when the CS:GO content path contains spaces. | Point it at a junction instead (`mklink /J C:\cscontent "<CS2>\csgo"`). |
| "Found no files matching specification". | The second argument (content root) is the folder that holds the VMF (`C:\source1`), not the CS:GO content folder. `-usebsp` needs the BSP in the legacy `csgo\maps`. |
| Raw BSPSource VMFs needed a Hammer open/save before the importer would take them. | `hammer_resave.py` reproduces exactly what that save changes (versioninfo, viewsettings, cordons, editor blocks, side `rotation`, %g planes, upper-case materials). |
| Entities on Valve's exclusion list (`source1import_map_entityexclusionlist.txt`) don't import (point_spotlight beams: `tools/spotbeam.py` rebuilds them as additive cones): `func_illusionary`, `point_spotlight`, `func_dustmotes`, `func_precipitation`, `env_lightglow`, `color_correction`, `env_tonemap_controller`, `postprocess_controller`, `fog_volume`, `func_areaportal*`, `func_occluder`, `func_viscluster`, `func_lod`, `shadow_control`, `info_lighting`, `env_detail_controller`, `water_lod_control`, bot patrol routes, and anything matching `tele.` / `teleport_triggers`. | `func_illusionary` becomes a never-solid `func_brush` before import (it's often visible decoration: 94 on mg_fred_all). The cosmetic ones are listed in the cleanup log so you can decide whether to rebuild them. |
| Brushes textured `toolsskybox`, `toolshint`, `toolsskip`, `toolsareaportal` or `toolsoccluder` are skipped, so sky brushes vanish and rooms open to the void. | Stage C rebuilds each dropped sky brush as a moondome box using the map's sky. |
| Many outputs are dropped, especially ones aimed at `!activator`. Also seen (ba_jail_keimusho): one of each double door's two outputs (`grdooright` + `grdoorleft` from the same trigger) went missing, or came back as a duplicate of the other leaf, leaving 10 doors that nothing opened. | Stage C diffs every entity's outputs against the decompiled VMF and puts the missing ones back. |
| The importer writes the main map as a keyvalues2 text `.vmap` plus prefabs. | Stage C collapses the prefabs and saves the map back as binary. |
| Displacements come through missing ("Found a displacement missing a needed subkey." in the import log; all 61 on mg_kohztec_course). | `tools/disprestore.py` rebuilds them from the BSP. Grep every import log for that line. |
| `info_particle_system` entities don't come across with the map's particles, since CS:GO particle systems aren't in CS2. | Use stock CS2 particles. Mario Party's torches use `particles/burning_fx/env_fire_tiny.vpcf`. Check `game\csgo\pak01_dir.vpk` for names: there are many `particles/burning_fx/env_fire_*` and `env_embers_*`. |
| An `info_particle_system` naming a stock CS:GO system (`effect_name dust_embers`, a .pcf name, not a path). | The importer can't map it ("WARNING: Failed to find source 2 file for particle system dust_embers"), keeps the bare name, the build says "FixupResourceName: Illegal path, missing extension" and nothing plays. CS2 ships most of them under the same name: all 20 our ports used (187 entities, 151 on mg_antique_course) are in csgo/pak01, one path each (`particles/maps/de_dust/dust_embers.vpcf`). Stage C `particles` (`tools/particles.py`, 8 Nov 2026; method from cs2-slop-porting 2026-11-08g, MIT) sets the path; custom .pcf systems are listed. |
| CS:GO materials with no source anywhere (custom textures not packed in the BSP). | Stage C rebuilds them from CS:GO's VPK if they're stock CS:GO, otherwise swaps in the closest stock CS2 material and flags it. Custom decals are left alone and flagged, because a random stock decal looks worse. |
| Some stock CS2 materials ship as stubs (error shader, no textures), so a CS:GO material of the same name looks broken. | Re-port the CS:GO material into the addon `vmap_refs.py` (stage B) lists stubs the map uses in `<addon>_stub_materials.txt`; stage C `assets` rebuilds them from CS:GO. Method from cs2-slop-porting. |
| A prop using a player model (a `tm_balkan` prop on mg_simpsons_course) makes the importer convert that model's whole animation set (2,654 animations). | `post_import_cleanup.py` now skips `models/player/` (and `maps/<addon>_skip_models.txt`); swap the prop for a stock CS2 character. |
| VTFCmd's `-output` flag flattens the folder tree (all PNGs land in one folder by bare name). | Leave out `-output` so each PNG is written next to its VTF. |
| The importer sanitises asset paths with spaces (`materials/schooufi texture/x.vmt` is referenced as `schooufi_texture/x.vmat`, `crash bandicoot/` → `crash_bandicoot/`), but `post_import_cleanup.py` converts the textures under their real names, so the vmap points at files that don't exist and the assets pass substitutes random stock materials. | `tools/matnames.py <addon> <root>` remaps the refs to the addon's real file names (needs `content_files_<addon>.json`). Run it before `alpha,assets`. mg_antique_course / mg_crash_bandicoot_course, 24 Oct 2026. |
| Static overlays (CS:GO infodecal / info_overlay) import as a 2x2 placeholder quad: tiny, flat on the default axis, often not on the surface. Some get a projection depth of 64, which shows as a 2x2x64 box and the overlay is invisible. | Stage C `overlayfix` (`tools/texfix.py`) rebuilds every untouched placeholder from the VMF: size = CS:GO texture x `$decalscale` (infodecal) or the info_overlay's own uv0..uv3 extent and StartU/EndU, laid on the brush face under the decal, origin 4 units off it, local +Z into the surface (Z = +normal makes it invisible), u mirrored and v flipped so the image reads correctly. Overlays edited by hand are left alone. `overlaydepth` also sets every overlay's projection depth to 8. Method from github.com/Ninja-Chris/cs2-slop-porting, 26 Oct 2026. |
| Brush face texture scale comes out absurd (e.g. 0.25/256) when the importer can't read the CS:GO texture, it reduces shifts to 0..16 and rounds axes, and Hammer draws the stored per-vertex texture coordinates, not the scale/shift numbers. | Stage C `facescale` (`tools/texfix.py`) matches each face to the VMF side on the same plane + material (overlapping brushes disambiguated by containment, axes, then shift mod 16), restores scale/axes/shift when the match is unambiguous or the scale is <0.01 / >8, and rewrites the texture coordinates with u = (P.axisU / scaleU + shiftU) / CS:GO texture width. Deliberate scales (0.125, 2, 4…) are kept. Same source, 26 Oct 2026. 29 Oct (from the 2026-10-28j version of that script, reimplemented): also matches renamed materials, moved copies of brushes (texture lock), rounded corners (2.5 u), faces pushed off their side (6 u), displacement faces (base-face mapping) and, for absurd scales, another material on the same plane; texture size from the addon's converted texture. Its results: unmatched faces jacs 299 → 0, goldeneye 299 → 296, tomgreens 15,630 → 11,734 (7,719 of them tools). |
| CS:GO `$additive` and `$nocull` are dropped. | Stage C `matflags`: every additive material moves to `csgo_unlitgeneric` with `F_BLEND_MODE 4` (confirmed additive and see-through). Lightmapped with `F_TRANSLUCENT 1` + `F_ADDITIVE_BLEND 1` keeps it lit, but a black additive material (mg_n64_goldeneye glass04) then draws opaque black in Hammer, so that is off (`LIT_ADDITIVE`). Alpha test and translucent are exclusive on the lit shaders. `$nocull` → `F_RENDER_BACKFACES 1` (+ `F_DONT_FLIP_BACKFACE_NORMALS 1` on lit shaders; Source 1 never flipped them). Finding from cs2-slop-porting 2026-10-28j. |
| `$ssbump` bump maps imported as normal maps light wrongly (they average ~(122,123,116) instead of ~(128,128,255)). | They hold light from Source 1's three radiosity basis directions. Stage C `matflags` rebuilds n = R*b0 + G*b1 + B*b2 (normalised) into `*_ssbn.png` and points `TextureNormal` at it. |
| Some stock CS2 sound files listed in the VPK index are stubs with no playable audio (e.g. `physics/metal/metal_grate_impact_*`). | Stage C `soundscripts` copies the CS:GO wave into the addon first and only falls back to the stock CS2 file. |
| An addon shows up in the Workshop Tools launcher as an example map that can't be edited. | `game\csgo_addons\<addon>\` still has the template's `readonly_tools_asset_info.bin` / `addoninfo.txt`. Delete both (working addons have neither). `prep.py` no longer copies them (24 Oct 2026). |
| The importer leaves copies of brush-entity geometry in the world at the entity's local coordinates (around 0 0 0). | Stage C `origindup` lists them (VMF brush entities moved to the origin, same materials, not on real world brushes); stage D `origindup` deletes them, only when they are in the way (skink52). From cs2-slop-porting 3.5 (MIT), 2 Nov 2026. |
| The importer culls a face another brush covers and treats an all-water brush as solid, so the face under the water (sea floor) disappears. | Stage C `culled`: the box is rebuilt from the VMF, nodraw except that face. From cs2-slop-porting 3.5 (MIT), 2 Nov 2026. |
| Outputs that target their own entity are dropped. | Stage C `io` (restore_io) already puts back every dropped output, these included. |
| Trigger volumes can store a hidden non-trigger material (copied floor brush; Hammer draws toolstrigger anyway); `tools*` materials referenced outside `materials/tools/`. | Stage C `trigmat` / `toolpaths`. From cs2-slop-porting 3.5 (MIT), 2 Nov 2026. |
| The importer writes `(null)` as the parameter of outputs that had none. | Stage C clears them before restoring dropped outputs (`nullparams`); before that, the diff with the VMF re-added a `""` copy and the output fired twice. From cs2-slop-porting 3.5 (MIT), 2 Nov 2026. |
| trigger_teleport / trigger_hurt / trigger_multiple spread over several meshes (or one mesh of separate pieces) | Don't work in game the way Hammer shows them (skink52, as in the cs2kz mapping notes). Stage C `trigsplit`: one entity per piece, same name, keyvalues and outputs; group them in Hammer afterwards if wanted. |

## Models, ModelDoc and weapons

| Problem | Fix |
|---|---|
| A **plugin-spawned** `custom_hud_layout` (CounterStrikeSharp) shows nothing; the client console says `Layout xml is an invalid resource name "panorama/layout/custom_game/x.vxml"`. | Give the layout as the **source name, `.xml`** (`panorama/layout/custom_game/x.xml`), as Hammer stores it in a map's entity; the client still loads the compiled `x.vxml_c`. Loose files, Workshop addons and precaching made no difference (6 Nov 2026, slime-mg-gm). |
| A custom player model's alpha-tested or translucent parts (a robe, hair, a whole body) are **invisible** in game: materials on `csgo_complex.vfx` aren't drawn on a player model (6 Nov 2026, GMod conversions: the grim reaper's robe, Rogue). | Use `csgo_character.vfx` for every player-model material; it takes `F_ALPHA_TEST` / `F_TRANSLUCENT` with `TextureTranslucency`. |
| Does a custom player model keep its own bone lengths, or do CS2's animations pull every bone back to the agent's? | **It keeps its own** (6 Nov 2026, in game): a copy of a model with its knee bones 8 u lower in the bind skeleton (mesh unchanged) bent at that lower knee with its feet still on the ground; the animations only rotate bones. So a model can be built on its own joint positions (CS2's bone names and hierarchy). One test model; check more before relying on it for odd proportions. |
| A cosmetic (hat, glasses) that should follow a player's head. CS2 agents have **no head attachment** (their attachments are knife, grenade0-4, c4, primary, eholster, pistol, clip_limit, weapon, weapon_hand_r/l, weapon_center), so `SetParent` + an attachment can't reach the head, and parenting to the pawn alone follows only its origin (no crouch, no head turn). | **Bone merge**: build the cosmetic on the agent skeleton (the template's body DMX, every vertex on `head_0`, `bone_cull_type "None"`) and `FollowEntity` the prop onto the pawn (CounterStrikeSharp `ent.AcceptInput("FollowEntity", pawn, pawn, "!activator")`, as cs2-store's equipment does): bones with the pawn's names take its pose. Works on any model with `head_0` (stock agents, our GMod conversions). `create/hats/`, [gmod-hats.md](../creation/gmod-hats.md). |
| The same cosmetic on a player model whose head isn't where a stock agent's is (GMod conversions keep their own heads, a median 3.6 u lower, skinned to `head_0`) floats above it: a bone merge can't be offset at run time. | Ship shifted copies as choices of one bodygroup (`fit`, 12 choices: 0 to -4.5 u down x -2/0/+2 u back/forward) and pick one per player model with `AcceptInput("SetBodygroup", ent, ent, "fit,<k>")`. |
| Running `cs_mdl_import -r` with a bare `*.mdl` scans the entire stock model tree and can crash (access violation) on an unrelated stock model, losing the whole batch. | Give it an explicit `-l` file list (`legacy/mdltovmdl.py`). |
| cs_mdl_import keeps a model's prop_data health but drops `explosive_damage` / `explosive_radius`, so props that relied on the model (ExplodeDamage 0 or unset) don't explode in CS2; ones with their own ExplodeDamage still do (ttt_island17: phys26 exploded, the other explosive barrels didn't). | `tools/propexplode.py` copies the model's values onto each such prop; CS2 still has the entity keys. |
| cs_mdl_import writes bodygroup choices with no name, and resourcecompiler refuses the whole model ("Invalid empty body group choice name in bodygroup 'X'. Non-empty choice names are required."), so every prop using it is missing in game (ttt_island17: 23 window bars and a door). | `tools/vmdlfix.py` names them `choice<N>` by index; maps switch bodygroups by index, so nothing changes. autoport runs it after every import. |
| One `.mdl`/`.dx90.vtx` checksum mismatch crashes the run and everything queued after it. | `legacy/newcheck.py` finds all the mismatched pairs first (studiohdr checksum at offset 8 vs the VTX header at offset 16). Exclude them, then fix them separately (Crowbar decompile/recompile). |
| cs_mdl_import converts geometry only. | Materials need their own pass (`post_import_cleanup.py` phases 2–3). |
| Unlit model materials (`UnlitGeneric` with `$basetexture`) can import as `TextureColor "[1 1 1]"`, so the model renders plain **white**. | Point `TextureColor` back at the texture. Mario Party's A/B flags were white because of this. |
| A custom CS:GO player model imports as a plain prop with no CS2 skeleton or animgraph: held weapons render huge, no ragdoll. | Rebuild it on the stock Phoenix agent skeleton (mg_mario_party's Octodad matched 73 bones; mg_50arenas' Power Ranger) and copy tm_phoenix's 14 ragdoll joints ([../creation/models.md](../creation/models.md#player-models)). |
| Props from other Source games that won't import. | Crowbar → Blender → ModelDoc, with alpha masks made from the textures. |
| ModelDoc turns SMD imports 90° about Z and reads V from the bottom (Space Racer tracks and cars came out 90° off). | Write SMD positions pre-rotated −90° (`(y, −x, z)`) with V flipped, or compensate with a yaw offset in script. For animation SMDs pre-rotate the root bone's position and rotation by −90° about Z (Puppet Brawl, Euler order R = Rz·Ry·Rx). Verified. |
| ModelDoc drops bones that have no geometry (and meshes made only of tool materials): an invisible animation rig compiled with zero bones, leaving bone-merged agents in T-pose. | A tiny triangle per bone hidden inside the body (material remapped to a real dark vmat) and `BoneMarkupList { bone_cull_type = "None" }` (Puppet Brawl). Verified. |
| ModelDoc material-group skins never switched when groups were remapped from the SMD material name. | Remap groups from the default group's material path (Hellmatch). |
| A ModelDoc model that only the script references (rig, effects) doesn't compile from the map build. | Open and save it in ModelDoc once, or compile it with `resourcecompiler -i <vmdl>`. |
| An imported CS:GO model with on/off bodygroups (`$bodygroup` with a `blank` option, e.g. `w_eq_bumpmine_dropped`'s `glow`) won't compile: "invalid empty body group choice name in bodygroup 'glow'" (and for the single-choice `studio` group). | Give every `BodyGroupChoice` in the vmdl a `name` (`"on"` / `"off"`); the first choice is the default (ba_jail_keimusho). |
| A `prop_dynamic` whose model has `prop_data` game data (imported CS:GO weapon/physics models, e.g. `w_eq_bumpmine_dropped`) | The map compile deletes it: "…uses model … which has propdata which means that it be used on a prop_physics or prop_door_xxx. DELETED." (ba_jail_keimusho's bump mine pool: the script found none of them). | Remove the `prop_data` GenericGameData block from the model's vmdl (`GameDataList children = [ ]`) when it's only for show, or use a physics/door class. Check the build log for DELETED lines. |
| `SetModel` (prop, weapon or pawn) to a model the map never loaded does nothing ("RESOURCE_TYPE_MODEL … requested is not loaded"). | Place a hidden "cache" `prop_dynamic` of every model the script uses. |
| Props the script moves. | `prop_dynamic` with `model_archetype ""`. Move them with `Move` every tick; a prop that is `Teleport`ed every tick is not drawn. |
| A prop with no physics hull is walk-through; a full-mesh hull on a weapon crashed on drop. | One convex hull per prop (or a few), never the render mesh. |
| LOD pops at ~300 u with `lod_thresholds` 12–60, and generated LOD1 meshes that shift parts. | Thresholds ×16 (192–480); ship LOD0 only where LOD1 deviates by ≥ ~2 u (mg_trenchwarfare shipped shelter/wire_coil/wreck_tank LOD0-only at ~2 u); keep geometry identical across LODs. |
| Blender FBX → ModelDoc materials. | Per-material custom string property `FBX_vmatPath` (live value, forward slashes, `materials/` prefix, no extension), Custom Properties ticked on export. |
| A door prop's pivot is in the wrong place and ModelDoc has no import translation. | Move the mesh in the source file, or an invisible `func_door_rotating` pivot with the prop parented. |
| The viewmodel can't be reached from cs_script (no `*viewmodel*` class at runtime). | Change view models through `weapons.vdata` ([../creation/custom-weapons.md](../creation/custom-weapons.md)). |
| Decompiling stock `scripts/weapons.vdata_c` throws "Unknown KVType … 26" in release Source 2 Viewer. | Use the Source 2 Viewer dev build (s2v.app), "Decompile & Export". A server's own vdata addon takes priority over a map's. |

## Lighting, materials and rendering

| Problem | Fix |
|---|---|
| A light a few units off a wall (torch, lamp fitting) bakes a blown-out spot and uneven light around it in CS2 (the course maps, both Minecraft maps). | `tools/lightwall.py` moves each light at least 24 u off any large face in front of it. |
| An animated CS:GO texture (AnimatedTexture proxy, a multi-frame VTF) on **tiled** world faces. CS2's `F_TEXTURE_ANIMATION` (`g_vAnimationGrid`, `g_nNumAnimationCells`) offsets the UV by one sheet cell per frame but never wraps inside the cell, so a face tiled more than once shows a window of the whole sheet that steps across it (looks like tearing / scrolling black bars, the sheet's padding). Fine only on 0..1 UV surfaces (screens, decals). Also: a sheet with alpha must be power-of-two or the texture fails to compile (`GenerateMips_AlphaWeighted: Cannot filter non-power-of-two texture`) and the material shows the error texture. | `tools/animprops.py`: the faces become skinned `prop_dynamic` models (one `csgo_unlitgeneric` vmat per frame, a material group per frame), the originals toolsnodraw, and the io script steps `Skin` at the frame rate (Hellmatch's method). Props on func_tracktrains are teleported onto the train and parented at round start, since trains move to their first path_track at spawn. mg_minecraft_adventure fire (84 frames) and lava (78), 4 Nov 2026. |
| Z-fighting where CS:GO had none: vbsp kept one of two coplanar overlapping faces, the importer keeps both meshes and CS2 draws both. | `tools/zfight.py`: fully covered faces → toolsnodraw, the smaller of two partly overlapping materials 0.25 u forward. Overlaps pressed against a back-facing face (props on a floor) can't be seen and are ignored; without that rule ttt_terrortrain listed 441, with it 9. |
| CS:GO lights import as **Static** (baked only), so weapons and player models are black. | Switch enough lights to Stationary (`directlight 3`): one or more per sealed compartment, no spot inside more than 4 stationary lights. |
| Lights the map switches on and off. | They must be **Dynamic** (`directlight 2`): Static lights can't switch off (de_rats_1337's 32 switchable lights). |
| Lights with `_fifty_percent_distance` come out far too bright (ttt_cg_skyscraper_2017's lower floors). | vrad falls back to linear falloff for them (I x 100 / d); the importer gave them ~8x a normal light and a 9,000-17,000 unit range. `lightbright` now matches them at 128 units, range 1600 x sqrt(legacy). |
| The importer makes `light_environment` Static (`directlight 1`): the sun lights nothing that moves, so outdoor maps look unlit (mg_jahoukarail_2015). | `directlight 3` (Stationary), plus at least one stationary light in every open-to-sky compartment (the `lights` pass does both). |
| Vents behind func_breakable grates bake pitch black (ttt_cg_skyscraper_2017). | `ventlight` pass: a dim unshadowed stationary light per duct, grates set to Disable Shadows. |
| CS2 has 4 shadow slots per area. | In lamp-heavy spaces make most lights unshadowed with capped range, 1–2 shadowed. mg_trenchwarfare's baked lamps: `light_omni2` with `brightness_units 1` (lumens), `brightness_lumens`, `range`, `directlight 3`, `castshadows 0/1`, `shape 0`; underground lamps cap the range at the distance to the surface −14 (70–130) so they don't light the terrain above. |
| A light the map switches (Enable / Disable / Toggle) left Static or Stationary | Its baked light stays on the walls when it is switched off. CS:GO's `TurnOn` / `TurnOff` don't exist on `light_omni2` and the other new lights, so those outputs did nothing at all (mg_galaxy_course's spawn lights). | Enable / Disable, and Direct Lighting Stationary (`directlight 3`: runtime direct light, baked shadows; switches and recolours fine, cheaper than Dynamic) with bounce light off. Dynamic only for lights riding a parent. More than 4 shadowed stationary lights over one spot don't fit CS2's shadow slots, so the extra ones get shadows off (they still light weapons). `mapcheck.py` fix does it. |
| A static `func_breakable` / `func_brush` (not attached to anything that moves) only partly inside a light probe volume is lit wrongly. | Cover the entire mesh with an `env_combined_light_probe_volume`. Stage C `probes` reports uncovered ones; `stage_d.py … probecover` adds volumes. (skink52, 27 Oct 2026) |
| Probe volumes only around a few static brushes (stage D `probecover`) and none over the play space | Hands, weapons and players almost black everywhere else (ttt_minecraft). | Stage D `probefill`: volumes over every cluster of spawns/teleports/weapons/lights/movers. |
| Overlapping light probe volumes | They don't blend: the highest Priority (`indoor_outdoor_level`, -2..2; there is no `priority` key) volume containing an object lights it (Valve wiki, env_light_probe_volume). ## Hammer and workflow

- Hammer keeps the open map in memory. Close it before a script edits the `.vmap`, or the edit is lost on the next save.
- **Never run resourcecompiler (or `build_maps.ps1`) with `C:\source1` as the working directory.** That folder holds a `gameinfo.txt` for the importer, so the compiler treats it as a game root and dies on every asset with `FATAL ERROR: C:\source1\pak01.vpk Failed to load file (unexpected)`; the asset pre-pass then reports every one of the addon's materials as not compiled (Nanite Temple, 3 Nov 2026). Run builds from `C:\source1\cs2port` (what `run_build.bat` does).
- Don't delete the stock `materials\tools` folders, even to replace them with custom versions. Deleting them broke Hammer's clip tool.
- Opening a map in Hammer compiles its materials. The command-line build doesn't, so it compiles assets explicitly first.
- The `.vmap` keeps its own list of the assets it references (`map_asset_references`, plus `map_subasset_reference_types/names/counts` per entity class).
  A stale list keeps Hammer reporting classes and scripts you've already removed (mg_50arenas). When a script adds or removes entities or materials,
  rewrite those lists from the real entities and strip stale material refs (Hellmatch, Space Racer).
- Moving outputs from a trigger onto a `logic_relay`: rename `OnStartTouch` to `OnTrigger`, or they never fire (yolo's scores).
- **Command-line map build with CS2 open** (7 Nov 2026, ba_jail_keimusho): works if CS2 is started **before** `resourcecompiler` and stays open
  until it ends. The compiler then uses the running game: quitting CS2 mid-build kills the compiler. Normal CS2 doesn't mount `csgo_addons`, so the
  built `.vpk` copies into `game\csgo_addons` with CS2 open. Hammer's `-threads 5` / `_threads 6` are low: logical cores - 2 (10) cut a final build
  from 70.6 to 49.3 min.
- Hammer while CS2 is running: a second instance with `cs2.exe -addon <name> -tools -steam -retail -insecure -noassetbrowser -vulkan` (≈2× RAM/VRAM;
  don't build while both have the addon mounted; untested).
