# CS2 gotchas: what breaks, and what fixed it

Collected from the ports in this repo and from the original cs_script addons (Hellmatch, Space Racer, mg_trenchwarfare, Puppet Brawl,
mg_deku_tree, the bomb-arena game). Port names in the Fix column point at `ports/<addon>/`; project names point at the project repos
listed in the [README](../../README.md#projects-built-with-this). Pipeline fixes run automatically in stage C (see
[pipeline.md](../porting/pipeline.md)). **Unverified** means it had not been confirmed in CS2 when it was written down. Detailed write-ups for
the original addons are in [../creation/](../creation/); cs_script API details are in [cs_script-notes.md](cs_script-notes.md).

## Valve's importer

| Problem | Fix |
|---|---|
| The importer fails with "pak01.vpk / Failed to load file (invalid)" while `game\bin\win64\vpk.signatures` exists, and Steam restores the file after updates. | Rename it (`run_import.bat` does it every run). |
| A material or texture file name containing `+` (CS:GO animated-texture frames such as `+0sign_compmon4_hr`) | resourcecompiler: "Non-fused-child compiles cannot contain fused delimiter '+'", so the material never compiles and the build stops (mg_n64_goldeneye). | Copy the vmat/png to a name without the `+N` prefix and repoint the meshes and the vmap's `map_asset_references`. Stage C flags them. |
| `item_assaultsuit` (or any `item_*`) in a `game_player_equip` `weaponN` slot | The server crashes while loading the map (null vtable call in the equip's weapon handling; mg_n64_goldeneye). | Keep only `weapon_*` in the slots and give items from cs_script (`pawn.GiveNamedItem("item_assaultsuit")`), fired next to the equip's trigger. Stage C does this. |
| Valve's importer writes `brightness = nan` on CS:GO lights whose intensity is below ~265 (it puts log2(I/265) in `brightness_legacy` and takes log2 again). | Hammer turns them into 0 on save; a command-line build gets nan. Stage C sets 0; `stage_d.py lightbright` rebuilds real values from the VMF. |
| `import_map_community.py` waits for Enter/Esc, so it can't run unattended. | `scripts/make_import_map_auto.py` makes a copy without the prompt. |
| The importer aborts the **whole** run on the first model or material it can't handle (`utlc.RunCommand` → `Error()` → `sys.exit(1)`). On a big map "it died" can mean anything from "barely started" to "only the compile didn't happen". | Run `post_import_cleanup.py` afterwards: it picks up where the importer stopped and reports what's still missing. |
| The importer fails when the CS:GO content path contains spaces. | Point it at a junction instead (`mklink /J C:\cscontent "<CS2>\csgo"`). |
| "Found no files matching specification". | The second argument (content root) is the folder that holds the VMF (`C:\source1`), not the CS:GO content folder. `-usebsp` needs the BSP in the legacy `csgo\maps`. |
| Raw BSPSource VMFs needed a Hammer open/save before the importer would take them. | `hammer_resave.py` reproduces exactly what that save changes (versioninfo, viewsettings, cordons, editor blocks, side `rotation`, %g planes, upper-case materials). |
| Entities on Valve's exclusion list (`source1import_map_entityexclusionlist.txt`) don't import: `func_illusionary`, `point_spotlight`, `func_dustmotes`, `func_precipitation`, `env_lightglow`, `color_correction`, `env_tonemap_controller`, `postprocess_controller`, `fog_volume`, `func_areaportal*`, `func_occluder`, `func_viscluster`, `func_lod`, `shadow_control`, `info_lighting`, `env_detail_controller`, `water_lod_control`, bot patrol routes, and anything matching `tele.` / `teleport_triggers`. | `func_illusionary` becomes a never-solid `func_brush` before import (it's often visible decoration: 94 on mg_fred_all). The cosmetic ones are listed in the cleanup log so you can decide whether to rebuild them. |
| Brushes textured `toolsskybox`, `toolshint`, `toolsskip`, `toolsareaportal` or `toolsoccluder` are skipped, so sky brushes vanish and rooms open to the void. | Stage C rebuilds each dropped sky brush as a moondome box using the map's sky. |
| Many outputs are dropped, especially ones aimed at `!activator`. | Stage C diffs every entity's outputs against the decompiled VMF and puts the missing ones back. |
| The importer writes the main map as a keyvalues2 text `.vmap` plus prefabs. | Stage C collapses the prefabs and saves the map back as binary. |
| Displacements come through missing ("Found a displacement missing a needed subkey." in the import log; all 61 on mg_kohztec_course). | `tools/disprestore.py` rebuilds them from the BSP. Grep every import log for that line. |
| `info_particle_system` entities don't come across with the map's particles, since CS:GO particle systems aren't in CS2. | Use stock CS2 particles. Mario Party's torches use `particles/burning_fx/env_fire_tiny.vpcf`. Check `game\csgo\pak01_dir.vpk` for names: there are many `particles/burning_fx/env_fire_*` and `env_embers_*`. |
| CS:GO materials with no source anywhere (custom textures not packed in the BSP). | Stage C rebuilds them from CS:GO's VPK if they're stock CS:GO, otherwise swaps in the closest stock CS2 material and flags it. Custom decals are left alone and flagged, because a random stock decal looks worse. |
| Some stock CS2 materials ship as stubs (error shader, no textures), so a CS:GO material of the same name looks broken. | Re-port the CS:GO material into the addon `vmap_refs.py` (stage B) lists stubs the map uses in `<addon>_stub_materials.txt`; stage C `assets` rebuilds them from CS:GO. Method from cs2-slop-porting. |
| A prop using a player model (a `tm_balkan` prop on mg_simpsons_course) makes the importer convert that model's whole animation set (2,654 animations). | `post_import_cleanup.py` now skips `models/player/` (and `maps/<addon>_skip_models.txt`); swap the prop for a stock CS2 character. |
| VTFCmd's `-output` flag flattens the folder tree (all PNGs land in one folder by bare name). | Leave out `-output` so each PNG is written next to its VTF. |
| The importer sanitises asset paths with spaces (`materials/schooufi texture/x.vmt` is referenced as `schooufi_texture/x.vmat`, `crash bandicoot/` → `crash_bandicoot/`), but `post_import_cleanup.py` converts the textures under their real names, so the vmap points at files that don't exist and the assets pass substitutes random stock materials. | `tools/matnames.py <addon> <root>` remaps the refs to the addon's real file names (needs `content_files_<addon>.json`). Run it before `alpha,assets`. mg_antique_course / mg_crash_bandicoot_course, 24 Oct 2026. |
| Static overlays (CS:GO infodecal / info_overlay) import as a 2x2 placeholder quad: tiny, flat on the default axis, often not on the surface. Some get a projection depth of 64, which shows as a 2x2x64 box and the overlay is invisible. | Stage C `overlayfix` (`tools/texfix.py`) rebuilds every untouched placeholder from the VMF: size = CS:GO texture x `$decalscale` (infodecal) or the info_overlay's own uv0..uv3 extent and StartU/EndU, laid on the brush face under the decal, origin 4 units off it, local +Z into the surface (Z = +normal makes it invisible), u mirrored and v flipped so the image reads correctly. Overlays edited by hand are left alone. `overlaydepth` also sets every overlay's projection depth to 8. Method from github.com/Ninja-Chris/cs2-slop-porting, 26 Oct 2026. |
| Brush face texture scale comes out absurd (e.g. 0.25/256) when the importer can't read the CS:GO texture, it reduces shifts to 0..16 and rounds axes, and Hammer draws the stored per-vertex texture coordinates, not the scale/shift numbers. | Stage C `facescale` (`tools/texfix.py`) matches each face to the VMF side on the same plane + material (overlapping brushes disambiguated by containment, axes, then shift mod 16), restores scale/axes/shift when the match is unambiguous or the scale is <0.01 / >8, and rewrites the texture coordinates with u = (P.axisU / scaleU + shiftU) / CS:GO texture width. Deliberate scales (0.125, 2, 4…) are kept. Same source, 26 Oct 2026. 29 Oct (from the 2026-10-28j version of that script, reimplemented): also matches renamed materials, moved copies of brushes (texture lock), rounded corners (2.5 u), faces pushed off their side (6 u), displacement faces (base-face mapping) and, for absurd scales, another material on the same plane; texture size from the addon's converted texture. Its results: unmatched faces jacs 299 → 0, goldeneye 299 → 296, tomgreens 15,630 → 11,734 (7,719 of them tools). |
| CS:GO `$additive` and `$nocull` are dropped. | Stage C `matflags`: every additive material moves to `csgo_unlitgeneric` with `F_BLEND_MODE 4` (confirmed additive and see-through). Lightmapped with `F_TRANSLUCENT 1` + `F_ADDITIVE_BLEND 1` keeps it lit, but a black additive material (mg_n64_goldeneye glass04) then draws opaque black in Hammer, so that is off (`LIT_ADDITIVE`). Alpha test and translucent are exclusive on the lit shaders. `$nocull` → `F_RENDER_BACKFACES 1` (+ `F_DONT_FLIP_BACKFACE_NORMALS 1` on lit shaders; Source 1 never flipped them). Finding from cs2-slop-porting 2026-10-28j. |
| `$ssbump` bump maps imported as normal maps light wrongly (they average ~(122,123,116) instead of ~(128,128,255)). | They hold light from Source 1's three radiosity basis directions. Stage C `matflags` rebuilds n = R*b0 + G*b1 + B*b2 (normalised) into `*_ssbn.png` and points `TextureNormal` at it. |
| Some stock CS2 sound files listed in the VPK index are stubs with no playable audio (e.g. `physics/metal/metal_grate_impact_*`). | Stage C `soundscripts` copies the CS:GO wave into the addon first and only falls back to the stock CS2 file. |
| An addon shows up in the Workshop Tools launcher as an example map that can't be edited. | `game\csgo_addons\<addon>\` still has the template's `readonly_tools_asset_info.bin` / `addoninfo.txt`. Delete both (working addons have neither). `prep.py` no longer copies them (24 Oct 2026). |

## Models, ModelDoc and weapons

| Problem | Fix |
|---|---|
| Running `cs_mdl_import -r` with a bare `*.mdl` scans the entire stock model tree and can crash (access violation) on an unrelated stock model, losing the whole batch. | Give it an explicit `-l` file list (`legacy/mdltovmdl.py`). |
| One `.mdl`/`.dx90.vtx` checksum mismatch crashes the run and everything queued after it. | `legacy/newcheck.py` finds all the mismatched pairs first (studiohdr checksum at offset 8 vs the VTX header at offset 16). Exclude them, then fix them separately (Crowbar decompile/recompile). |
| cs_mdl_import converts geometry only. | Materials need their own pass (`post_import_cleanup.py` phases 2–3). |
| Unlit model materials (`UnlitGeneric` with `$basetexture`) can import as `TextureColor "[1 1 1]"`, so the model renders plain **white**. | Point `TextureColor` back at the texture. Mario Party's A/B flags were white because of this. |
| A custom CS:GO player model imports as a plain prop with no CS2 skeleton or animgraph: held weapons render huge, no ragdoll. | Rebuild it on the stock Phoenix agent skeleton (mg_mario_party's Octodad matched 73 bones; mg_50arenas' Power Ranger) and copy tm_phoenix's 14 ragdoll joints ([../creation/models.md](../creation/models.md#player-models)). |
| Props from other Source games that won't import. | Crowbar → Blender → ModelDoc, with alpha masks made from the textures. |
| ModelDoc turns SMD imports 90° about Z and reads V from the bottom (Space Racer tracks and cars came out 90° off). | Write SMD positions pre-rotated −90° (`(y, −x, z)`) with V flipped, or compensate with a yaw offset in script. For animation SMDs pre-rotate the root bone's position and rotation by −90° about Z (Puppet Brawl, Euler order R = Rz·Ry·Rx). Verified. |
| ModelDoc drops bones that have no geometry (and meshes made only of tool materials): an invisible animation rig compiled with zero bones, leaving bone-merged agents in T-pose. | A tiny triangle per bone hidden inside the body (material remapped to a real dark vmat) and `BoneMarkupList { bone_cull_type = "None" }` (Puppet Brawl). Verified. |
| ModelDoc material-group skins never switched when groups were remapped from the SMD material name. | Remap groups from the default group's material path (Hellmatch). |
| A ModelDoc model that only the script references (rig, effects) doesn't compile from the map build. | Open and save it in ModelDoc once, or compile it with `resourcecompiler -i <vmdl>`. |
| `SetModel` (prop, weapon or pawn) to a model the map never loaded does nothing ("RESOURCE_TYPE_MODEL … requested is not loaded"). | Place a hidden "cache" `prop_dynamic` of every model the script uses. |
| Props the script moves. | `prop_dynamic` with `model_archetype ""`. Move them with `Move` every tick; a prop that is `Teleport`ed every tick is not drawn. |
| A prop with no physics hull is walk-through; a full-mesh hull on a weapon crashed on drop. | One convex hull per prop (or a few), never the render mesh. |
| LOD pops at ~300 u with `lod_thresholds` 12–60, and generated LOD1 meshes that shift parts. | Thresholds ×16 (192–480); ship LOD0 only where LOD1 deviates by ≥ ~2 u (mg_trenchwarfare shipped shelter/wire_coil/wreck_tank LOD0-only at ~2 u); keep geometry identical across LODs. |
| Blender FBX → ModelDoc materials. | Per-material custom string property `FBX_vmatPath` (live value, forward slashes, `materials/` prefix, no extension), Custom Properties ticked on export. |
| A door prop's pivot is in the wrong place and ModelDoc has no import translation. | Move the mesh in the source file, or an invisible `func_door_rotating` pivot with the prop parented. |
| The viewmodel can't be reached from cs_script (no `*viewmodel*` class at runtime). | Change view models through `weapons.vdata` ([../creation/custom-weapons.md](../creation/custom-weapons.md)). |
| Decompiling stock `scripts/weapons.vdata_c` throws "Unknown KVType … 26" in release Source 2 Viewer. | Use the Source 2 Viewer dev build (s2v.app), "Decompile & Export". A server's own vdata addon takes priority over a map's. |

## Lighting, materials and rendering

| Problem | Fix |
|---|---|
| CS:GO lights import as **Static** (baked only), so weapons and player models are black. | Switch enough lights to Stationary (`directlight 3`): one or more per sealed compartment, no spot inside more than 4 stationary lights. |
| Lights the map switches on and off. | They must be **Dynamic** (`directlight 2`): Static lights can't switch off (de_rats_1337's 32 switchable lights). |
| Lights with `_fifty_percent_distance` come out far too bright (ttt_cg_skyscraper_2017's lower floors). | vrad falls back to linear falloff for them (I x 100 / d); the importer gave them ~8x a normal light and a 9,000-17,000 unit range. `lightbright` now matches them at 128 units, range 1600 x sqrt(legacy). |
| The importer makes `light_environment` Static (`directlight 1`): the sun lights nothing that moves, so outdoor maps look unlit (mg_jahoukarail_2015). | `directlight 3` (Stationary), plus at least one stationary light in every open-to-sky compartment (the `lights` pass does both). |
| Vents behind func_breakable grates bake pitch black (ttt_cg_skyscraper_2017). | `ventlight` pass: a dim unshadowed stationary light per duct, grates set to Disable Shadows. |
| CS2 has 4 shadow slots per area. | In lamp-heavy spaces make most lights unshadowed with capped range, 1–2 shadowed. mg_trenchwarfare's baked lamps: `light_omni2` with `brightness_units 1` (lumens), `brightness_lumens`, `range`, `directlight 3`, `castshadows 0/1`, `shape 0`; underground lamps cap the range at the distance to the surface −14 (70–130) so they don't light the terrain above. |
| A static `func_breakable` / `func_brush` (not attached to anything that moves) only partly inside a light probe volume is lit wrongly. | Cover the entire mesh with an `env_combined_light_probe_volume`. Stage C `probes` reports uncovered ones; `stage_d.py … probecover` adds volumes. (skink52, 27 Oct 2026) |
| With no light probe volume, brush entities (doors, platforms, buttons), props, players and weapons don't get the baked light, so they look brighter or darker than the walls. | `env_combined_light_probe_volume` over each room (Mario Party, mg_draw_course). Sizes that worked on mg_trenchwarfare: voxel 64 on the battlefield, 108 on far strips (no overlap with neighbouring probes), 32 in tunnels, 48 in the lobby. |
| Dark indoor maps whose light came from the sky through ceilings. | `daylight` pass (stage D): a stationary sun, ceilings set to cast no shadows, probe volumes, and higher `maxexposure` (mg_draw_course). |
| Lightmap bake stalled in charting ("26669 unique meshes") with every prop forced to `bakelighting 1` × LODs. | Light-probe foliage, wire and props under ~40 u (`bakelighting 0`); cover outer areas with probe volumes (mg_trenchwarfare). |
| vrad3 `FATAL ERROR: OUT OF MEMORY` at "Welding seams", and packing needs a bigger `lightmapMaxResolution` every build ("Packing 5603771 UV charts"). | Every LOD of every lightmapped prop is charted, and every disconnected piece is a chart. Decimated LODs with per-face vertices made each triangle a chart. Share LOD vertices and give lightmapped props two LODs at most (`create/lod_decimate.py --lightmapped-from`); keep wire probe-lit (mg_trenchwarfare tw34: 5.6M → 1.37M charts, bakes at 2048). |
| Frame rate drops (200 → ~70) every ~0.5 s on a listen server with bots on a big nav mesh (44k areas). | `bot_kick` confirms it; turn bots off by default from the script (`bot_quota 0` + `bot_kick` on activate) and let admins opt in (mg_trenchwarfare tw35). |
| "No lightmap resolution volumes set". | Only lowers lightmap texel density. Closed `toolslightmapres.vmat` meshes over the player space (64 grid, floor to +128) plus one box per room. |
| `vrad3` `VK_ERROR_OUT_OF_DEVICE_MEMORY` on an Intel Arc B580. | Driver/ReBAR or CPU lighting, and lightmap resolution volumes to cut charts (untested). |
| `csgo_complex` with `F_TRANSLUCENT 1` but no `TextureTranslucency` draws opaque (the colour texture's alpha isn't used); `csgo_unlitgeneric` ignores `F_TRANSLUCENT` altogether (mg_yolo_multigames banners and wireframe walls). | Always give a `TextureTranslucency` mask; on unlitgeneric use `F_BLEND_MODE 1`/`2`. |
| `$alphatest` / `$translucent` materials import **opaque**, so cut-out letters, fences, glass and decals turn into solid squares. | Add `F_ALPHA_TEST` or `F_TRANSLUCENT` with a `TextureTranslucency` mask made from the texture's alpha. |
| Alpha-tested textures must be power-of-two. | Pad (adjust the UVs) or stretch to the next power of two (Hellmatch pads sprites, stretches tiling textures). |
| `csgo_unlitgeneric` blend modes. | `F_BLEND_MODE` 0 opaque, 1 translucent, 2 alpha test (with `TextureTranslucency` + `g_flAlphaTestReference "0.500"`), 4 additive; `g_vColorTint` tints, `g_flModelTintAmount "1.000"` lets script `SetColor` tint the prop (Hellmatch, Space Racer). |
| CS:GO water shaders don't exist (no waterfall shader at all). | Stock `materials/liquids/nuke_water.vmat` on a closed volume with the water material on top and nodraw elsewhere. Reflections come from a baked cubemap. Water sheets must never overlap (two sheets z-fight); mg_trenchwarfare used `hr_aztec_water_shallow.vmat` with depth capped at 5 u. |
| Map water meets the 3D skybox water with a hard edge (mg_pirates). | The main map draws over the skybox: the main water has to fade out at its edges (csgo_water_fancy `g_vMapUVMin/Max` = the water's XY extent, `g_flSkyBoxFadeRange`, Valve uses 0.1-0.2 on Anubis/Overpass), nothing of the main map may sit under the water in the fade band (sea bed), skybox probe volume edges must not cross the water, and both waters need the same settings. Stock vmats can't be edited: decompile with `tools/vmatc.py`. `tools/waterblend.py` does all of it (cs2kz mapping guide, "Infinite water"). Untested in game yet. |
| Old stock vmat_c files show params the current shader no longer has (Anubis' skybox water: `F_SIMPLE_SKYBOX`, `g_flSimpleSkyScale`). | Check the shader's own list (shaders_pc `csgo_water_fancy_pc_50_features.vcs`, zstd KV3) before copying params from a stock material. csgo_water_fancy texture inputs: TextureDebris, TextureDebrisHeight, TextureDebrisNormal, TextureFoam, TextureFoamNormal, TextureLowEndCubeMap, TextureWavesHeight, TextureWavesNormal. |
| `env_sun` doesn't exist. | `light_environment` draws the sun. Remove `env_sun`. |
| Overlays become meshes, and their alpha is lost. | `csgo_static_overlay` with a translucency mask from the original alpha. For decals with a solid background, key the mask from the most common border colour (mg_smee_tower_cs2, de_rats_1337). Overlays that come out too bright can be toned down with `g_fTextureColorBrightness` (0.3 on ba_jail_lightsout). |
| `csgo_unlitgeneric` `g_vTexCoordScrollSpeed` does nothing in CS2. | Animated prop whose frames are the texture shifted `max(2, w/32)` px (max 32 frames), stepped by the script with the `Skin` input (one material group per frame; Hellmatch). The other route, unverified: `F_TEXTURE_ANIMATION 1`, `g_nNumAnimationCells "N"`, `g_vAnimationGrid "[N 1]"`, `g_flAnimationTimePerFrame "0.07"`, frames side by side (Space Racer, untested in CS2; also Valve's TV-static material). |
| Backface culling. | `$nocull` ports need `F_RENDER_BACKFACES 1`; crossed-plane sprite materials set it too (Hellmatch). Hellmatch's notes once said CS2 drew both faces of its model polygons, but its code sets the flag on sprites and builds mirrored back faces for voxel slabs, so that is **unverified**. Check the material's flags instead of assuming. |
| Stock vmats with `F_VERTEX_ANIMATION` (wind, e.g. `maple_tree_bark_1`) look wrong on static props; legacy `vertexlitgeneric` stock materials (palletwood, kasbah planks, cloth01) have flat normals. | Export a non-animated `csgo_complex` copy of the texture, or pick a `csgo_complex` stock material. |
| Self-lit model parts (tracers, sight pips). | `csgo_vertexlitgeneric` + `F_SELF_ILLUM`. |
| Terrain blending. | Valve blend materials (e.g. `hr_ancient_blend_groundmud03-groundgrass_01_wet`), `VertexPaintBlendParams.x` = layer B weight, `VertexPaintTintColor`. Copy the mesh stream layout from `content/csgo/maps/editor/zoo/ancient_zoo.vmap`. |
| `effect_textureOverride` on a shared stock particle (glow01) changes every glow01 in the map. | A dedicated vpcf per texture. Hand-written vpcf that "isn't precached correctly": open and re-save it in the Particle Editor. |
| A Panorama HUD panel bigger than its parent (e.g. a 250% spinning layer) gets squished back to the parent size, so its edges show. | `overflow: noclip noclip;` on the parent (and the layout root), and size the layer in px (mg_yolo_multigames drugged overlay: 4000 px squares). |
| CS:GO "Refract" screen overlays and `color_correction` have no CS2 equivalent. | Keep the colour as a `post_processing_volume` with a 32³ RGB `.raw` LUT (`CColorLookupColorCorrectionLayer`). |
| A custom camera close to a wall clips through it (CS2's near clip plane; eye 15 u forward, collision radius 16). Scripts can't change the near plane. | A hidden render-only copy of each wall up to 16 u behind it, same material; tall step faces and low lintels too. See-through dropped from ~99% to <1% (Hellmatch). |

## Sky and world

| Problem | Fix |
|---|---|
| CS:GO skies aren't in CS2. | Rebuild the six CS:GO faces into a 2:1 equirect panorama (`sky.py`). HDR skies are tone mapped. The pipeline's `sky.vfx` vmat sets only `SkyTexture`; Space Racer's and Hellmatch's also set `F_TEXTURE_FORMAT2 1` and `g_flBrightnessExposureBias "0.000"`. Which of those is needed is **unverified**: check on the next sky port. |
| A 3D skybox: CS2 ignores `sky_camera`, so the skybox geometry becomes part of the map. | Move it to a separate skybox map referenced by `skybox_reference` (`tools/skysplit.py`; mg_pirates, ttt_cg_skyscraper_2017, mg_awp_submarine, mg_bombardment, mg_enjoy_multigames, mg_yolo_multigames, ba_jail_skylight, ba_jail_lightsout). If it doesn't render: untick **Editor only** on the skybox map's `sky_camera` (ba_jail_lightsout). |
| The 3D skybox draws behind everything. | Nothing players or vehicles can get near may live in it. The skybox map needs `mapUsageType skybox`, its own `light_environment` + `env_sky` and a `sky_camera` (scale 16); the main map gets a `skybox_reference` (mg_trenchwarfare: `targetMapName maps/<map>_3dskybox.vmap`, `fixupNames 1`, `worldGroupID skyboxWorldGroup0`, origin 0 0 0, skybox geometry authored at world/16 around the `sky_camera`). |
| Sky shells around arenas / dropped sky brushes (moondomes). | **New in the late-October 2026 CS2 update:** a `toolsskyboxocclude` tool material that does the job of the moondome shells (a surface that shows the sky and closes off the void). Reported by skink52; not yet tested in our maps or wired into the pipeline, which still writes `csgo_moondome` shells. Check the exact material path in Hammer's tools materials before scripting it. |
| A moondome whose sky is a stock CS2 sky (`sky_cs15_daylight01_hdr`). | Its `TextureCubeMap` pointed at a panorama png that was never built (stage C only builds one for skies CS2 lacks), so it compiled as an error (mg_pirates). Stage C now builds the panorama for the moondome too, or falls back to toolsskybox. |
| A `toolsskybox` shell always shows the single `env_sky`. | Several skies in one map: one moondome box per area with its own sky material and no toolsskybox shell (Space Racer; whether `csgo_moondome` accepts an equirect `TextureCubeMap` is unverified). |
| Areas open to the sky bake pitch black under rebuilt moondome sky shells (ttt_minecraft). | The sun and sky light bake through `toolsskybox`, not through a csgo_moondome mesh: stage C now rebuilds dropped sky brushes as toolsskybox (`skyshell` pass for older ports). Untested in game yet. |
| The importer drops tiny brush entities: ttt_cg_skyscraper_2017's btn1/btn3 (1×1×1-unit `toolsnpcclip` func_buttons) were missing from the CS2 map. | Compare the BSP entity lump / VMF with the vmap by name and class; `tools/restore_ents.py` puts them back. |
| A crash with no script error: CS2 writes `cs2_<date>_accessviolation.mdmp` to `game\bin\win64`. | Read the exception and stack from it (the minidump format is simple to parse by hand; `objdump -d` disassembles `game\csgo\bin\win64\server.dll` at the crash address). A script call shows as `v8.dll` frames under the server.dll binding. cs2mapTTT's kill crash was traced this way to a prop_ragdoll Teleport. |
| A moondome (sky-material shell) hides a 3D skybox: it draws on top of it (ttt_cg_skyscraper_2017's rebuilt sky brushes would have covered the city skyline). | On maps with a 3D skybox the dropped sky brushes must come back as `materials/tools/toolsskybox.vmat`; stage C `sky` now does that when the VMF has a `sky_camera` or the map a `skybox_reference`. The skybox map's own shells too: `skysplit.py` swaps both maps (`--sky` for a map already split). |

## Vis and compile

| Problem | Fix |
|---|---|
| Vis voxelises every vis-relevant face at 8 units. Big sky shells around every room dominated: Mario Party took 19.2M nodes and 103 s to voxelise, plus 62 s of outside detection. | Mark sky shells "Exclude from Vis" where the room is already sealed by its own walls (`visfit.py`; `skyvis.py` is the older shell-only pass), and give each room its own hint box. Mario Party went to 3.6M nodes, 23 s voxelise, 27 s outside detection. |
| After that, a multi-room map's vis time is clustering, line-of-sight sampling and cluster merging: Mario Party still spent 27 min in vis, mostly merging 12,963 clusters down to the 4,096 cap (560 s) and LOS rays (444 s). | Fewer initial clusters is the lever: Lower (`hintType` 8) instead of Low on big rooms. Not yet tried on Mario Party. |
| Hint types (base.fgd) | 0 High (8), 1 Normal (8), 10 Reduced (16), 2 Medium (32), 3 Low (64), 8 Lower (64, fewer initial clusters), 9 Lowest (256, fewest clusters). |
| High or Medium hints over big arena boxes explode the cluster count: Mario Party's Medium arena hints gave 1,451,170 regions and 663 s of clustering. Lowest everywhere (256-unit regions) makes walls vanish a few steps back. | Ports: Low over the walkable band, Lower over the rest, one Lowest over everything, no Medium (`visfit.py`). Original multi-arena maps: Low over each arena, Lowest over the void, Medium only in small dense spots; for a very large total volume use Lower (mg_50arenas: 53 boxes, about 60 times a normal map's volume). |
| mg_egypt_course's vis stalled in the final cluster merge: 35,254 clusters after the list merge (other maps got to 13-39k), then 2,308 s to merge only to 32,768 (135 s per pass, against about 1 s on mg_draw_course), with 4,094 as the target. The build was stopped after 51 min. Its long open halls have almost nothing that blocks vis (2,172 triangles), so most clusters see each other. | Fewer clusters to start from: hints fitted to the play space with Lower (`hintType` 8) instead of Low everywhere (`stage_d.py ... visfit_lower`). Build it last in a queue so a stall doesn't hold up the other maps. |
| Region counts don't follow hint volume: mg_draw_course's 6 Low boxes covered about 7,000 regions' worth of volume, but it got 258,371 regions. They follow vis surface area much more closely (roughly 300 to 1,400 regions per million square units across six maps). | Shrinking hint boxes helps most where it moves space players never stand in out of Low, but surface detail still costs. Keep detail that doesn't need to block sight Excluded from Vis. |
| `toolsnodraw` doesn't block vis and is ignored by the inside/outside test (Valve's Source 2 visibility docs). Clips, triggers and meshes marked Exclude from Vis don't count either. Imported func_detail comes in already Excluded from Vis (993 of egypt's 1,187 world meshes). | When checking whether a room is sealed for vis, use only vis-relevant geometry. Several ports (e.g. mg_galaxy_course) are enclosed only by nodraw, so in vis terms they're open. |
| Overlapping visibility_hints: the highest-resolution one governs (Valve docs). Low (3) and Lower (8) are both 64-unit grids, so which one wins where they overlap is unclear. | Keep Low and Lower boxes from overlapping. One Lowest over everything underneath is fine. |
| `prop_static` models (visoccluder off) never block vis; fine hints over prop-only levels cost huge compile time (36 Low hints → 1.8M regions, 1013 s). | Low hints only along the play band, Lowest elsewhere. |
| Open maps make vis slow: mg_circle_course's open centre took 18+ min (2,453,840 clusters). | Iterate without full vis and keep the sealed volume as small as the playable space. |
| A command-line build writes the `.vpk` only to its `-outroot`. Hammer copies it into `game\csgo_addons\<addon>\maps\` itself, so early command-line builds seemed to do nothing. | `build_maps.ps1` copies it and checks the size. |
| Starting the next compile before that `.vpk` is copied caused clashes. | Build one map at a time and copy the `.vpk` before the next one starts. |
| A command-line map build doesn't compile materials Hammer never loaded, and a missing material makes its meshes fail ("Failed loading resource materials/lasers/…vmat_c"). Its pre-pass covers `maps/scripts/*.js` and `panorama/*.vtex` only: older-layout `scripts/*.js` and `panorama/layout/custom_game/*.xml` / `panorama/styles/custom_game/*.css` need `resourcecompiler -f -i <file>` (Puppet Brawl). |
| A heavy environment prefab is too big to collapse in Hammer (ba_jail_lightsout: about 15 MB, 1,457 entities). | Open the prefab on its own, copy everything, then Paste Special into the main map. The pipeline now collapses prefabs directly in the `.vmap`. |
| Build logs look garbled, and some lines look like errors. | They're UTF-16LE (`iconv -f UTF-16LE -t UTF-8`). | Loading pictures: naming. | CS2 loads `panorama/images/map_icons/screenshots/1080p/<map>_png` (compiled), then `<map>_1_png` … The canonical rule and both ways of producing it are in [pipeline.md](../porting/pipeline.md#loading-screen-background-images). |
| With a single loading picture your art doesn't show (Space Racer, Hellmatch: nothing at all was shown). | Ship at least two (`<map>`, `<map>_1` … `_9`); they play as a slideshow, 4 s each, starting on a random one. Ports with only one picture (ba_jail_skylight, jb_water_prison_cs2) should get a second. |
| Loading pictures not compiled. | Reference them from a never-shown rule in the HUD stylesheet (they show from the second load), or compile with `run_build.bat "assets <addon>"`. |
| Content hidden behind CS2's loading UI. | 1920×1080 slide, scaled to cover the screen (driven by `panorama/scripts/loadingscreen.vts`). CS2 draws a 300 px column 20 px from the right with the slide blurred behind it; 4:3 loses 240 px each side, 21:9 crops top and bottom. Keep content in x 252–1348 and y 104–948 (Hellmatch / hud.md); Space Racer's `loading.py` uses y 128–952 for the 21:9 crop. |
| Renamed map ships its old files too. | Delete the old `maps/<old>.vpk`, `_cameras.txt`, `_retakes.txt`, overview txt and compiled panorama images from content and game before uploading. |
| Workshop upload carries the compiled game folder, not content. | Licence and credit files must be in the game folder and/or the description. |
| Servers loading a Workshop map. | `host_workshop_map <id>` (Hellmatch's server requirements). |
| Steam Workshop pages read through a page fetcher all say "removed" / "incompatible". | Hidden template text; never report an item as removed from it ([details](../porting/pipeline.md#before-porting-duplicate-check-and-names)). |

## Hammer and workflow

- Hammer keeps the open map in memory. Close it before a script edits the `.vmap`, or the edit is lost on the next save.
- Don't delete the stock `materials\tools` folders, even to replace them with custom versions. Deleting them broke Hammer's clip tool.
- Opening a map in Hammer compiles its materials. The command-line build doesn't, so it compiles assets explicitly first.
- The `.vmap` keeps its own list of the assets it references (`map_asset_references`, plus `map_subasset_reference_types/names/counts` per entity class).
  A stale list keeps Hammer reporting classes and scripts you've already removed (mg_50arenas). When a script adds or removes entities or materials,
  rewrite those lists from the real entities and strip stale material refs (Hellmatch, Space Racer).
- Moving outputs from a trigger onto a `logic_relay`: rename `OnStartTouch` to `OnTrigger`, or they never fire (yolo's scores).
- Hammer while CS2 is running: a second instance with `cs2.exe -addon <name> -tools -steam -retail -insecure -noassetbrowser -vulkan` (≈2× RAM/VRAM;
  don't build while both have the addon mounted; untested).
